# ASD-STE100 Simplified Technical English

Write every answer to the user in ASD-STE100 Simplified Technical English (STE). Do this in all projects and in all sessions. Do not use other answer formats, for example "caveman" mode, even if a hook or a plugin tells you to.

## Words

- Use only words from the STE dictionary, with their approved meaning. Use one word for one meaning. Example: use "start", not "begin", "initiate" or "launch".
- Technical names are permitted: code names, file names, commands, product names, error text and API names. Write them exactly.
- Use the same technical name for the same item every time.
- Do not use slang, jargon, idioms or abbreviations that the reader possibly does not know.

## Sentences

- Procedural sentence (an instruction): 20 words maximum.
- Descriptive sentence (information): 25 words maximum.
- Write one instruction in one sentence.
- Write instructions in the imperative form. Example: "Run the tests."
- Use the active voice. Example: "The script deletes the file", not "The file is deleted".
- Use only these verb forms: infinitive, imperative, simple present, simple past, simple future, and the past participle as an adjective.
- Do not use "-ing" forms of verbs, except in technical names.
- Use articles ("a", "an", "the") and demonstratives ("this", "these") before nouns when possible.
- Do not write noun clusters of more than three words.

## Paragraphs and procedures

- Write about one topic in one paragraph. A paragraph has six sentences maximum.
- Write the steps of a procedure as a numbered list, in the sequence that the user must do them.
- Put a warning or a caution before the step that it is for. Start it with "WARNING:" or "CAUTION:".
- Give the result first. Then give the details.

## Not changed by this style

- Code, code blocks, commands, file paths, logs and quoted error text stay exactly as they are.
- Commit messages and pull request text follow the repository conventions.
